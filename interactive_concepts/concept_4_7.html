Durable Execution

Temporal & Restate — workflows that survive crashes, handle retries automatically, and guarantee exactly-once execution

The Problem: Long-Running Agents Are Fragile

"An agent running a 2-hour research task that touches 10 APIs, processes 500 documents, and costs $50 in compute — crashes after 1h 50min. Do you restart from scratch? Durable execution means you don't."

💥 Process Crash

Server runs OOM or gets restarted by k8s. All in-memory state is gone.

🌐 Network Timeout

External API times out after 30s. Without retry logic, the whole workflow fails.

⏱️ Multi-Day Tasks

Agent waits 24h for a human approval. A process cannot stay alive in memory for 24 hours.

💳 Partial Completion

Payment charged, but order not created — crash mid-transaction leaves data inconsistent.

What is Durable Execution?

Durable execution frameworks record every step your code takes to an event log. If the process crashes, the framework replays the log to restore exact state — completed steps are skipped, and execution resumes from the exact failure point. Your workflow code looks like normal sequential Python, but it gains crash-safety, automatic retries, and exactly-once guarantees automatically.

# ❌ Fragile — crash between steps = data inconsistency def process_order(order): payment = charge_card(order) # ← crash here = charged but no order inventory = reserve_stock(order) # never runs shipment = book_shipping(order) # never runs send_confirmation(order) # never runs # ✅ Durable — crash = replay from last checkpoint @workflow.defn class ProcessOrderWorkflow: @workflow.run async def run(self, order: Order) -> str: payment = await workflow.execute_activity(charge_card, order) inventory = await workflow.execute_activity(reserve_stock, order) shipment = await workflow.execute_activity(book_shipping, order) await workflow.execute_activity(send_confirmation, order) return shipment.tracking_id

Temporal vs Restate

⏱️ Temporal

  • Battle-tested — used at Uber, Netflix, Stripe
  • Go + Java + Python + TypeScript SDKs
  • Workflow = code (not YAML/DSL)
  • Signals (async messages to running workflows)
  • Queries (read live workflow state)
  • Schedules (cron-like workflow triggers)
  • Heavy infrastructure (Temporal server + DB)
  • Best for: enterprise, existing Java/Go teams

🔁 Restate

  • Newer, cloud-native — simpler ops story
  • TypeScript + Java + Python (Rust core)
  • Embedded durable promises in functions
  • Service mesh friendly — HTTP native
  • Serverless-compatible (Lambda, Deno Deploy)
  • Simpler local dev experience
  • Lighter weight than Temporal
  • Best for: cloud-native, serverless, new projects

Saga Pattern — Compensation for Failures

When a workflow step fails mid-way, the Saga pattern runs compensation actions to undo previously completed steps. Click each step to see its forward action and compensation.

Forward Action
✓ Charge customer card ($149.99)
Compensation
↩ Refund $149.99 to card

Payment is the first step. If ANY later step fails, this compensation issues a full refund. Idempotency key prevents double-charging on retry.

async with saga.compensate_on_failure(): saga.add_compensation(refund_payment, payment_id) payment = await charge_card(order, idempotency_key=order.id)
Forward Action
✓ Reserve inventory (SKU-2291 × 2)
Compensation
↩ Release inventory reservation

Inventory is reserved but not removed. If shipping fails, the reservation is released so stock is available for other orders.

saga.add_compensation(release_inventory, reservation_id) reservation = await reserve_stock(sku="SKU-2291", qty=2)
Forward Action
✓ Book courier (UPS Next Day)
Compensation
↩ Cancel courier booking

If notification fails, we still need to cancel the booked courier and release the slot — otherwise we get billed for an unneeded shipment.

saga.add_compensation(cancel_booking, booking_id) booking = await book_courier(warehouse="EU-West", service="next_day")
Forward Action
✓ Send order confirmation email
Compensation
↩ No-op (email is fire-and-forget)

Email delivery cannot be "undone" — if it was sent, it's sent. The compensation is a no-op, but retrying is safe since the email is idempotent (same order ID = no duplicate).

await send_email(to=order.email, template="order_confirmed", data=order, idempotency_key=f"confirm_{order.id}")

When to Use Durable Execution

ScenarioDurable Needed?Why
Single LLM call (<30s)NoFast, stateless — retry at call site is enough
Multi-step agent (minutes)MaybeDepends on cost and external side-effects
Long-running agent (hours)YesProcess will be restarted; replay needed
Multi-day task with human pauseYesCannot hold state in memory for days
Financial transactionsYesExactly-once and compensation required
Tasks touching external APIsYesIdempotency + retry saves re-charging
Simple data processing pipelineMaybeIdempotent batch jobs can use simpler retry

Temporal Agent Workflow — Full Example

import asyncio from datetime import timedelta from temporalio import activity, workflow from temporalio.client import Client from temporalio.worker import Worker # ── Activities = individual steps ────────────────────────────────────── @activity.defn async def research_topic(topic: str) -> str: """Step 1: Web research (can fail, will be retried).""" return await web_search(topic) @activity.defn async def analyse_findings(findings: str) -> dict: """Step 2: LLM analysis.""" return await llm.structured_output(analyse_prompt + findings) @activity.defn async def write_report(analysis: dict) -> str: """Step 3: Generate final report.""" return await llm.complete(report_prompt + str(analysis)) # ── Workflow = durable coordinator ──────────────────────────────────── @workflow.defn class ResearchWorkflow: @workflow.run async def run(self, topic: str) -> str: # Each execute_activity is automatically: # - Retried on failure (up to 10 times with backoff) # - Recorded to event log (crash-safe) # - Skipped on replay (exactly-once) findings = await workflow.execute_activity( research_topic, topic, start_to_close_timeout=timedelta(minutes=5) ) analysis = await workflow.execute_activity( analyse_findings, findings, start_to_close_timeout=timedelta(minutes=2) ) report = await workflow.execute_activity( write_report, analysis, start_to_close_timeout=timedelta(minutes=3) ) return report # ── Client: start the workflow ───────────────────────────────────────── async def main(): client = await Client.connect("localhost:7233") result = await client.execute_workflow( ResearchWorkflow.run, "Agentic AI trends 2025", id="research-001", # deterministic ID = idempotent task_queue="research-queue", ) print(result)
