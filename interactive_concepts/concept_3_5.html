A2A Discovery: The Agent Card

The JSON document at /.well-known/agent.json that tells the world what an agent can do — A2A's discovery mechanism.

Agent Card Anatomy — Click a Field

"name": "ResearchAgent", "description": "Web research and summarization", "url": "https://agents.acme.com/research", "version": "1.2.0", "defaultInputModes": ["text/plain"], "defaultOutputModes": ["text/plain", "application/json"], "capabilities": { "streaming": true, "pushNotifications": false }, "skills": [{ "id": "web-research", "name": "Web Research", "description": "Search and summarize", "tags": ["research", "search"], "examples": ["Summarize AI trends"] }], "securitySchemes": { "bearerAuth": { "type": "http", "scheme": "bearer" } }

Discovery Flow

🤖 Caller Agent

Needs a research agent

→

GET /.well-known/agent.json

Fetch from target domain

→

Parse Agent Card

Read skills, caps, auth

→

Cache Card

TTL from Cache-Control

→

tasks/send

Now start delegation

Step 1 — Fetch: The calling agent does a simple HTTP GET to https://target-agent-domain.com/.well-known/agent.json. No auth needed — discovery is public.

Step 2 — Validate: Parse the JSON and confirm the agent has the skills needed (check skills[].tags and skills[].description).

Step 3 — Check capabilities: Verify capabilities.streaming if you need live updates. Check defaultInputModes to know what content types to send.

Step 4 — Auth setup: Read securitySchemes to understand how to authenticate. Then obtain credentials via that scheme before calling tasks/send.
