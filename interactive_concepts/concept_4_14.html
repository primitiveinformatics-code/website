Multi-Hop Strategies
🔄
Iterative Retrieval
Agent retrieves, inspects result, decides next query — adaptive and LLM-driven

Best for: Open-ended questions where next hop depends on what you find

Downside: Sequential — slower than parallel approaches

retrieve("CEO of OpenAI") → "Sam Altman" → retrieve("Sam Altman background") → Answer synthesized
🌳
Sub-Question Decomposition
Break complex query into sub-questions, retrieve each in parallel, combine results

Best for: Multi-part questions with independent sub-questions

Advantage: Can run sub-queries in parallel for speed

Q: "Compare GPT-4 vs Claude 3" → Q1: "GPT-4 capabilities" → Q2: "Claude 3 capabilities" → Q3: "Benchmark results" → Combine → Answer
🕸️
Graph-Based Traversal
Nodes = documents, edges = relationships — traverse the knowledge graph hop by hop

Best for: Entity-relationship questions over structured knowledge

Requires: Knowledge graph or entity linking layer

Entity: "Anthropic" → Edge: "founded_by" → Entity: "Dario Amodei" → Edge: "previously_at" → "OpenAI" → Answer
⚡
Beam Search RAG
Maintain top-K hypotheses at each hop — prune weak paths, keep promising chains

Best for: Long reasoning chains where wrong hops compound errors

Trade-off: More retrievals but higher answer quality

Hop 1: [A, B, C] retrieved Prune to top-2: [A, B] Hop 2 from A: [A1, A2] Hop 2 from B: [B1, B2] Best path: A → A2 → Answer
When to Use Each Approach
Question Type Approach Why
"Papers about RAG from 2024 rated >4.5" Self-Query Has metadata constraints — pre-filter wins
"What did the CEO of Company X say about AI?" Multi-Hop Must first find CEO, then find quote
"Compare product A vs B across all dimensions" Multi-Hop (Sub-Q) Multiple independent retrievals
"Latest Python tutorials for beginners" Self-Query Category + recency filters suffice
"How does X affect Y via mechanism Z?" Multi-Hop (Graph) Entity relationship traversal needed
