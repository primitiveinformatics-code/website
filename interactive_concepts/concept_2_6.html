Planning Strategies

Good planning dramatically reduces tool-call count and cost on complex tasks. The right strategy depends on task structure. Choosing incorrectly costs 3–10× more tokens and produces worse results. This is one of the highest-leverage decisions in agent design.

The 4 Planning Strategies — Explore Each

Chain of Thought (CoT)

Sequential reasoning before action
Token Cost
Low
The simplest planning strategy: prompt the agent to "think step by step" before taking any action. Instead of jumping directly to a tool call, the agent articulates its reasoning chain first. This dramatically reduces wrong first moves on complex problems.
Prompt: "Think step by step before answering."
→ Agent Thought: "Step 1: I need X. Step 2: To get X I need Y. Step 3: I'll call tool_A..."
→ Action: tool_A(params)
→ Repeat
Best for
Linear problems where one correct path exists. Default for most tasks.
Key benefit
Zero additional infrastructure. Just a prompt instruction. Reduces hallucination on multi-step tasks.
Limitation
Only explores ONE path. If it goes wrong early, no recovery without starting over.
Implemented in
All major frameworks — just add "think step by step" to the system prompt

Tree of Thoughts (ToT)

Multi-path exploration with evaluation
Token Cost
High
The agent explores multiple solution branches simultaneously, evaluates each one's promise, and selects the best path forward. Think of it as running several parallel CoT chains and picking the winner. More powerful but significantly more expensive.
Generate 3 candidate approaches → Evaluate each → Select best
→ Expand best branch → Generate 3 sub-approaches → Evaluate
→ Repeat until solution found or depth exceeded
Best for
Problems with multiple valid approaches where the best path isn't obvious upfront (code debugging, creative writing, complex reasoning).
Key benefit
Doesn't get stuck on one wrong path. Explores solution space. Can backtrack.
Limitation
2–5× more expensive than CoT. Requires evaluation logic. Overkill for routine tasks.
Rule of thumb
Use when a wrong first step is very costly and hard to recover from

Reflexion

Learn from failure across attempts
Token Cost
Medium
The agent reviews its own failed attempts and explicitly articulates WHY they failed before retrying. Unlike simple retry logic, Reflexion extracts a lesson from each failure and uses it to inform the next attempt. It uses Episodic Memory to store past attempts.
Attempt 1 → Fails → Store in Episodic Memory
→ Reflect: "Why did Attempt 1 fail? What would I do differently?"
→ Attempt 2 with refined plan → Fails again → Store
→ Reflect: "What BOTH attempts got wrong..."
→ Attempt 3 informed by all prior failures
Best for
Tasks where quality matters more than speed. Code generation, complex reasoning, tasks that benefit from iterative refinement.
Key benefit
Agent gets smarter across attempts. The failure analysis itself generates new, useful reasoning.
Limitation
Requires Episodic Memory. Multiple attempts = higher latency. Set a max retry limit (3–5 typically).
Uses
Episodic Memory to store past attempt logs + outcomes for the reflection step

ReWOO

Reasoning Without Observation — parallel execution
Token Cost
Lowest
ReAct is serial — it waits for each tool result before planning the next step. ReWOO (Reasoning Without Observation) generates the FULL plan upfront with placeholders, then executes all tool calls IN PARALLEL. Dramatically faster and cheaper for predictable workflows.
Plan phase (ONE LLM call):
Step1: search_web("query1") → Result1
Step2: search_web("query2") → Result2
Step3: calculate(Result1, Result2) → FinalAnswer

Execute phase (PARALLEL):
Step1 && Step2 run simultaneously → results fill placeholders
Step3 runs with filled values → FinalAnswer
Best for
Tasks where the full sequence can be articulated BEFORE executing any step. Data pipelines, report generation, structured research.
Key benefit
Decouples slow LLM reasoning from fast tool execution. 2–5× latency improvement over ReAct for predictable tasks.
Limitation
Less adaptive — if Step 3 depends on Step 1's result in unexpected ways, the pre-made plan breaks. Use ReAct when steps are highly interdependent.
Decision rule
Can you write the full plan before executing ANY step? → Use ReWOO
Which Strategy to Use? — Decision Guide
Start at the top. Follow the branch that matches your task.
Q1: Can you write the FULL plan with all tool calls BEFORE executing any?
✓ Yes
The workflow is predictable.
→ Use ReWOO for parallel execution + lowest token cost
✗ No
Each step depends on the last.
→ Continue to Q2
Q2: Does quality matter more than speed? Is wrong-first-step costly?
✓ Yes (high-stakes)
Wrong early steps are expensive to recover.
→ Use Tree of Thoughts to explore multiple paths
✗ No (standard task)
Reasonable first path is fine.
→ Continue to Q3
Q3: Does this task benefit from learning from failures? (Code, complex reasoning)
✓ Yes
Iterative refinement improves quality significantly.
→ Use Reflexion with Episodic Memory + max 3–5 retries
✗ No
Standard task, reasonable path.
→ Use Chain of Thought — simplest, cheapest, default choice

Key Takeaway
Planning strategy is one of the highest-leverage decisions in agent design. The default (Chain of Thought) works for most tasks at minimum cost. For predictable parallel workflows, ReWOO can cut latency 5×. For iterative quality improvement, Reflexion. For high-stakes exploration, Tree of Thoughts. Wrong strategy choice = 3–10× unnecessary token spend with worse results.
