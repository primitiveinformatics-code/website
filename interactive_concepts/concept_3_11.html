Session 3 · Concept 3.11

Structured Outputs

Why agents need deterministic, machine-readable responses — and how to enforce them with JSON Schema and Pydantic.

Why Agents Need Structured Outputs
The Core Problem: LLMs are stochastic text generators. Without enforcement, they might say "The answer is 42" one run and "42\n\nHope that helps!" the next. Downstream code that tries to parse either response will break. Structured outputs force the model to emit valid, schema-conformant data every time.
🔗

Chaining Agents

Agent A's output becomes Agent B's input. Any hallucinated field name or unexpected nesting breaks the entire pipeline silently.

🗄️

Database Writes

Saving to a database requires exact field types. A string "null" where a boolean false is expected corrupts your data layer.

🖥️

UI Rendering

A React component expects user.name but the model returns user.full_name. The UI crashes or shows empty fields.

🔍

Testability

You cannot write reliable unit tests against free-form text. Structured outputs make agent behavior deterministic and auditable.

Enforcement Methods
Define the Schema
# The contract you give to the LLM
schema = {
  "type": "object",
  "properties": {
    "action": {
      "type": "string",
      "enum": ["search", "answer", "clarify"]
    },
    "query": { "type": "string" },
    "confidence": {
      "type": "number",
      "minimum": 0, "maximum": 1
    }
  },
  "required": ["action", "confidence"],
  "additionalProperties": false
}
Validate the Response
import jsonschema

def validated_call(prompt, schema):
    response = llm.call(
        prompt=prompt,
        response_format={
            "type": "json_object"
        }
    )
    data = json.loads(response)

    # Raises ValidationError if
    # schema not satisfied
    jsonschema.validate(data, schema)
    return data
Key constraint: Always set "additionalProperties": false — otherwise the model can add extra fields that silently break downstream consumers.
Define with Pydantic v2
from pydantic import BaseModel, Field
from typing import Literal, List
from enum import Enum

class AgentAction(str, Enum):
    SEARCH = "search"
    ANSWER = "answer"
    CLARIFY = "clarify"

class AgentDecision(BaseModel):
    action: AgentAction
    query: str | None = None
    confidence: float = Field(
        ge=0.0, le=1.0
    )
    reasoning: str = Field(
        min_length=10
    )
Parse & Validate
import json

def get_decision(context: str):
    raw = llm.call(
        prompt=f"Analyze: {context}",
        response_format={
            "type": "json_object"
        }
    )

    # Pydantic validates AND coerces
    decision = AgentDecision(
        **json.loads(raw)
    )

    # Now fully type-safe!
    if decision.action == \
       AgentAction.SEARCH:
        return run_search(decision.query)

OpenAI Structured Outputs (Nov 2024+): Pass a Pydantic model or JSON Schema directly as response_format. The API guarantees the output matches the schema — no parsing fallbacks needed.
Using Pydantic Class
from openai import OpenAI
from pydantic import BaseModel

class ExtractedData(BaseModel):
    name: str
    age: int
    skills: list[str]

client = OpenAI()
response = client.beta.chat\
    .completions.parse(
        model="gpt-4o-2024-08-06",
        messages=[...],
        response_format=ExtractedData
    )

# Already a typed object!
data = response.choices[0]\
    .message.parsed
Refusal Handling
# Always check for refusal!
msg = response.choices[0].message

if msg.refusal:
    # Model refused to comply
    handle_refusal(msg.refusal)
elif msg.parsed:
    # Safe to use
    process(msg.parsed)
else:
    # Shouldn't happen but
    # handle defensively
    handle_empty()
Instructor library: Provider-agnostic wrapper that patches any LLM client to support Pydantic validation with automatic retry on validation failure. Works with OpenAI, Anthropic, Gemini, and local models. 
import instructor
from anthropic import Anthropic
from pydantic import BaseModel, Field

# Patch the client once
client = instructor.from_anthropic(Anthropic())

class TaskBreakdown(BaseModel):
    tasks: list[str] = Field(min_length=1, max_length=10)
    estimated_minutes: int = Field(gt=0)
    priority: Literal["low", "medium", "high"]

# Instructor handles retries automatically if validation fails
result = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    response_model=TaskBreakdown,
    max_retries=3,   # Retry with validation error feedback
    messages=[{"role": "user", "content": "Break down: build a login page"}]
)

# result is a TaskBreakdown instance — fully typed, fully validated
print(result.tasks)  # ['Design UI', 'Implement form', ...]

Schema Enforcement

This is the critical gate. Either the model's response format is constrained at API level (OpenAI Structured Outputs, Anthropic's tool use schema) or validated post-response with jsonschema/Pydantic. Failed validation triggers a retry or escalation — never silently passes bad data downstream.

Common Failure Modes & Fixes
🔄 Hallucinated Enum Values
▶
Model returns "action": "lookup" but your schema only allows "search" | "answer" | "clarify". Validation fails but the model keeps trying the same wrong value.

Why: The model infers what seems reasonable rather than reading the constraint.
✓ Fix: Include enum values in the system prompt. "Valid actions: search, answer, clarify — no others."
📦 Nested Schema Drift
▶
Schema defines result.items[].id as integer but model returns it as string. Works in Python (implicit cast) but breaks in typed languages or strict validators.

Why: JSON has no native integer type — "1" and 1 look similar to the model.
✓ Fix: Use Pydantic's strict mode or add type coercion at the boundary layer.
🚫 Missing Required Fields
▶
Model returns valid JSON but omits a required field. Pydantic raises ValidationError but with no retry logic, the pipeline crashes.

Why: Model optimizes for "reasonable" response — may omit fields it deems irrelevant.
✓ Fix: Use Instructor with max_retries=3. The validation error is fed back as context for self-correction.
📝 Markdown Contamination
▶
Model wraps JSON in a markdown code block: ```json\n{...}\n```. Direct json.loads() fails with a syntax error.

Why: Model was trained to present code nicely for humans.
✓ Fix: Use response_format: json_object at API level, or strip markdown with a pre-parser before validation.
