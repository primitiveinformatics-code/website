MCP: Model Context Protocol

The open standard that lets AI agents securely discover and call external tools — a universal plug for capabilities.

What Is MCP?

🔌

Universal Plug

One protocol to connect any AI model to any tool or data source — no custom integrations per model.

📜

Open Standard

Released by Anthropic in 2024; now adopted by OpenAI, Google DeepMind, and major IDE makers.

🔒

Security-First

Servers declare capabilities explicitly. Clients request only what they need. No implicit access.

⚡

Stateful Sessions

Unlike REST, MCP maintains session state so agents can have multi-turn tool conversations.

Transport Layer & Message Types

Used for local MCP servers running on the same machine (CLI tools, IDE plugins, desktop agents).

1

Client spawns server process

The MCP client starts the server as a subprocess: node mcp-server.js

2

Communication via stdin/stdout

Client writes JSON-RPC messages to the server's stdin; reads responses from stdout

3

Newline-delimited JSON

Each message is a single JSON line terminated by \n — no framing headers needed

4

Process lifecycle tied to client

Server process exits when client disconnects — no persistent background service required

Used for remote MCP servers accessible over HTTP (cloud APIs, shared team servers).

1

Client opens SSE connection

HTTP GET to /sse endpoint — server keeps connection open for streaming events

2

Client sends requests via HTTP POST

Tool calls sent as HTTP POST to /message endpoint with JSON-RPC body

3

Server streams responses over SSE

Results flow back through the open SSE stream as data: events — enables streaming

4

Auth via HTTP headers

Bearer tokens, API keys, or OAuth passed in standard Authorization headers

MCP defines three JSON-RPC message types for client–server communication.

R

Request

Client → Server. Has an id, method, and optional params. Expects a response.

P

Response

Server → Client. Matches id of the request. Contains result or error.

N

Notification

Either direction. No id — fire-and-forget. Used for progress updates and logs.

Tool Definition (Server → Client)

"tools": [{
  "name": "search_web",
  "description": "Search the web for current info",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {
        "type": "string",
        "description": "Search query"
      }
    },
    "required": ["query"]
  }
}]

Tool Call (Client → Server)

{
  "jsonrpc": "2.0",
  "id": 42,
  "method": "tools/call",
  "params": {
    "name": "search_web",
    "arguments": {
      "query": "MCP protocol spec 2024"
    }
  }
}

MCP vs Alternatives

Cross-model standard ✓ Yes ✗ OpenAI only ✗ ChatGPT only ✗ Custom per API
Tool discovery ✓ Dynamic ~ Predefined JSON ~ OpenAPI spec ✗ Hardcoded
Stateful sessions ✓ Built-in ✗ Stateless ✗ Stateless ~ Manual
Streaming support ✓ SSE native ~ Streaming API ✗ No ~ Depends

Resources & prompts ✓ First-class ✗ Not in spec ✗ Not in spec ✗ No standard
