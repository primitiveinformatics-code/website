The 4 Types of Memory

Without memory, every agent loop iteration starts from scratch. Memory is what makes agents coherent, efficient, and capable over long multi-step tasks. Each of the 4 types serves a distinct role — knowing which to use, and when, is the difference between a functional agent and an expensive one.

Explore Each Memory Type

Working Memory

≈ RAM · Context Window

Working memory is everything the agent can "see" right now — the system prompt, the current task, conversation history, and the results of recent tool calls. It lives inside the context window and is rebuilt fresh for every LLM call.

Computer analogy: RAM. Fast, immediately accessible, but completely lost when the process ends. You can't fit your entire hard drive into RAM — same as you can't fit all knowledge into the context window.
▸Finite capacity: 8K–200K tokens depending on model
▸Volatile: cleared at end of session or when context is reset
▸When full: use context compression — summarise old turns
▸Failure mode: "Context Drift" — system prompt gets pushed back, agent forgets its directive

Episodic Memory

≈ Activity Log · Past Episodes

Episodic memory is a structured log of what the agent did in past sessions — sequences of actions, what worked, what failed, and why. It's the backbone of the Reflexion pattern, where agents review failed attempts and plan better on the next try.

Computer analogy: Application logs or an audit trail. You can query it to understand what happened, replay specific sequences, and identify recurring failure patterns.
▸Stores sequences of (action, observation, outcome) tuples
▸Enables Reflexion: agent reviews why attempt N failed, retries smarter
▸Persistent across sessions — survives context resets
▸Implementation: SQLite/PostgreSQL log, retrieved via timestamps or episode IDs

Semantic Memory

≈ Hard Drive · Knowledge Base

Semantic memory is the agent's long-term factual knowledge store — documents, policies, product manuals, code repositories, customer data. Stored as vector embeddings, retrieved by semantic similarity (RAG). This is what gives agents access to private company knowledge.

Computer analogy: Your hard drive — vast, persistent, but you must explicitly look things up. The key technology is the vector database, which retrieves by meaning rather than exact keyword match.
▸Stored as vector embeddings (1,536 floats per chunk)
▸Retrieved via cosine similarity search (RAG pipeline)
▸Powers access to private data LLMs were never trained on
▸Tools: Pinecone, Weaviate, ChromaDB, pgvector
Speed
Fast (ANN search)
Capacity
Millions of chunks
Persistence
High (vector DB)
Use in agents

Human brain equiv.
General world knowledge ("Paris is the capital of France")

Procedural Memory

≈ Muscle Memory · Skills

Procedural memory is the agent's library of HOW to do things — reusable prompt templates, workflow patterns, few-shot examples that teach the agent how to approach recurring task types. It's implicit knowledge baked into the system prompt or retrieved as-needed.

Computer analogy: Saved scripts, macros, or function libraries. Rather than re-solving how to format a report from scratch each time, the agent has a template that captures best practice.
▸Stored as prompt templates and few-shot example libraries
▸Injected into the system prompt or working memory on demand
▸Reduces token cost and reasoning overhead for routine tasks
▸Learned over time via Reflexion — successful strategies become templates

Key Takeaway
Memory architecture is one of the most important design decisions in agentic AI. Working memory is finite — once it fills up, the agent degrades. Long-running tasks need Semantic memory (RAG) for knowledge and Episodic memory for continuity. Production agents combine all four types, each serving its specific role.
