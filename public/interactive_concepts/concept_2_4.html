Session 2 · Concept 2.4

The BDI Rationality Loop

How a BDI agent cycles through perception, reasoning, and commitment — the heartbeat of rational agent behaviour.

The 5-Step Rationality Loop — Click Each Step

The BDI Rationality Loop is the continuous cycle that governs how a rational agent perceives its world, updates its mental state, and decides what to do. Click each step to explore it.

1
Perceive Environment
Sense inputs from the world — messages, tool results, sensor data

The agent reads its environment: incoming messages, tool results, API responses, sensor readings, or any external information stream. This is the agent's window to the world — it forms the raw material for belief updates.

In code: This is where observation tokens enter the context window. The agent's context now contains new information it didn't have before.

→ Feeds Belief Update
2
Update Beliefs
Revise the agent's world model based on new perceptions

Based on what was perceived, the agent updates its Beliefs — its internal model of the world's current state. Old beliefs that are contradicted by new evidence are revised. New facts are added.

Example: Agent believed file X existed. Perception says file not found. Belief updated: file X does NOT exist; plan must change.

Belief State Updated
3
Generate / Revise Options (Desires)
What could the agent do? Generate candidate goals and sub-goals

Given its updated Beliefs, the agent generates a set of possible desires — things it could pursue. These are candidate goals, not yet committed to. The agent evaluates which desires are achievable and relevant given the current world state.

Example: "Could retry with alternative API" and "Could skip this document and continue" and "Could ask user for help" — all generated as options.

Desires Evaluated
4
Select Intention (Commit)
Choose ONE option to commit to — becoming an Intention

The agent commits to one desire, turning it into an Intention. This is the most critical step in the rational agent loop — selecting WHAT to pursue drives all subsequent actions. The committed intention remains stable unless the world changes dramatically.

Key insight: Intentions are resistant to change — they provide motivational stability. An agent that abandons intentions too easily wastes resources replanning constantly.

Intention Committed
5
Execute Action
Carry out the chosen intention, then loop back to Perceive

The agent executes its intention — calling a tool, sending a message, writing to memory, or taking any other action. The result of this action becomes input to the next perception cycle, closing the loop.

Loop continuation: After execution, the agent returns to Step 1 — perceiving the result of its own action. This is what makes it a loop, not a one-shot process.

→ Loop Restarts at Step 1

In the BDI Rationality Loop, what happens to Beliefs when a tool returns an unexpected result?
✗a) Beliefs are ignored — only Intentions matter
✓b) Beliefs are updated to reflect the new reality, which may trigger new Desires and a new Intention
✗c) The loop halts until a human provides new beliefs
✗d) The agent retries the same action until it succeeds
✓ Right. The rationality loop's power is this cascading update: Perception → Belief Update → new Desire options → potentially a new Intention. When a tool returns an error, the agent updates its belief ("the API is down"), generates new desires ("retry with backup API", "skip and log"), selects one, and commits. No human intervention required.
✗ The whole point of the rationality loop is autonomous adaptation. When perception brings unexpected results, Beliefs are updated first — then Desires are regenerated based on the new beliefs — then a new Intention is selected. The agent doesn't ignore it, halt, or blindly retry. It updates its world model and reasons anew.
Question 2 of 5
Why are Intentions described as "resistant to change" in the BDI model?
✗a) Because the agent's code prevents changing intentions at runtime
✗b) Because intentions are stored in long-term memory and are permanent
✓c) Because constant replanning wastes resources — stability in commitments is computationally efficient
✗d) Because changing intentions requires human approval
✓ Exactly. Motivational stability is a core BDI design principle. An agent that abandons its intentions the moment a slightly better option appears will spend all its resources replanning and never executing. Intentions should persist unless the world changes dramatically enough to make them unachievable or no longer relevant. This is called the "commitment strategy."
✗ It's not about code constraints or permanent storage. The BDI model deliberately makes intentions "sticky" because constant replanning is computationally wasteful. If an agent reconsiders its plan at every perception cycle, it spends more time deliberating than acting. Intentions are meant to be stable commitments that provide a stable direction for action — changed only when the world changes significantly.

At which step does an agent move from "what I could do" to "what I will do"?
✗a) Step 2 — Update Beliefs
✗b) Step 3 — Generate Options (Desires)
✓c) Step 4 — Select Intention (Commit)
✗d) Step 5 — Execute Action
✓ Step 4 is the commitment moment — where the agent narrows from a set of candidate Desires to a single committed Intention. "What I could do" = Desires (multiple options). "What I will do" = Intention (singular commitment). Step 5 is just execution of the already-decided intention.
✗ Step 3 generates multiple candidate options (Desires = what the agent could do). Step 5 executes after the decision is made. The transition from "could do" to "will do" happens at Step 4 — Select Intention — when the agent commits to one option from among its desires. This commitment is the defining act of rational choice in the BDI model.
Question 4 of 5
How does the BDI Rationality Loop differ from a simple ReAct loop?
✗a) ReAct has more steps
✓b) BDI explicitly models mental states (Beliefs, Desires, Intentions) as separate components; ReAct is a prompt-level trace pattern
✗c) BDI is newer than ReAct
✗d) They are identical — BDI is just a renamed version of ReAct
✓ Correct distinction. ReAct (Reason+Act) is a prompting strategy — a structured thought/action/observation trace pattern used with LLMs. BDI is an agent architecture theory from academic AI (Bratman, 1987) that explicitly defines three separate mental state types and how they interact. Modern LLM agents implement ReAct-style traces that approximate BDI reasoning, but they're different abstraction levels.
✗ BDI (from 1980s AI theory) is an architectural model that explicitly defines Beliefs, Desires, and Intentions as separate cognitive components with defined relationships. ReAct is a 2022 prompting technique that structures LLM output as Thought→Action→Observation traces. BDI is a theoretical framework; ReAct is a practical implementation pattern. They're not the same — but modern agents often implement BDI principles via ReAct-style traces.
Question 5 of 5
What triggers the BDI loop to RECONSIDER an existing Intention rather than just executing it?
✗a) A timer expiry after a fixed interval
✗b) User sends a new message
✓c) A significant change in Beliefs that makes the current Intention unachievable or irrelevant
✗d) The agent always reconsiders at every loop iteration
✓ Exactly. Intention reconsideration is triggered by Belief changes — specifically when the world has changed enough that the current intention is either (a) no longer achievable, or (b) no longer relevant to the agent's goals. Minor environmental noise doesn't trigger reconsideration (that would be computationally wasteful). Only significant belief updates — like "the target resource no longer exists" — warrant abandoning and re-selecting an intention.
✗ Timers are an external mechanism, not intrinsic to BDI. User messages are one form of perception but not the only trigger. The agent does NOT always reconsider at every cycle — that's the commitment stability problem. The BDI trigger for reconsideration is a significant belief update that makes the current intention either unachievable (world has changed) or irrelevant (goal already achieved or superseded).
