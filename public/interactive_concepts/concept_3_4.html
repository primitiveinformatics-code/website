3.4 — A2A Protocol
Session 3 · Tool Ecosystems

A2A Protocol

Agent-to-Agent communication standard — how autonomous agents delegate tasks to each other across organizational boundaries.

What Is A2A?

🤝

Agent Collaboration

A2A lets one AI agent delegate tasks to another agent — even across different vendors, clouds, or organizations.

📋

Task-Oriented

Unlike MCP's tool calls, A2A exchanges are full tasks with rich state: submitted → working → completed.

🌊

Streaming-Native

Long-running tasks stream status updates and partial artifacts back to the caller in real time via SSE.

🔒

Opaque Execution

The remote agent is a black box — caller doesn't know (or care) how it works internally. Just tasks in, results out.

MCP vs A2A — When to Use Which

DimensionMCP (Tool Protocol)A2A (Agent Protocol)
Unit of exchangeTool call (function)Task (multi-step work)
CounterpartyDeterministic serviceAutonomous agent
Execution modelSynchronous, fast (<2s)Async, long-running (secs–mins)
State managementStateless per callTask has lifecycle (5 states)
StreamingOptionalFirst-class via SSE
Discoverytools/listAgent Card (/.well-known/agent.json)
AuthAPI keys / OAuthOAuth 2.0 (required)
Typical useSearch, DB query, file readResearch, coding, writing tasks

💡 Rule of thumb: Use MCP to call tools. Use A2A to delegate to agents. They're complementary — an A2A agent often uses MCP internally to call its own tools.

Core Protocol Messages

1

tasks/send

Client agent sends a task to the remote agent. Includes: task_id, session_id, message with parts (text, file, data).

2

tasks/sendSubscribe

Like tasks/send but opens an SSE stream — server pushes TaskStatusUpdateEvent and TaskArtifactUpdateEvent as work progresses.

3

tasks/get

Poll the current task state and any artifacts produced so far. Used when not using SSE streaming.

4

tasks/cancel

Request cancellation of an in-progress task. Remote agent should stop and set state to canceled.

5

tasks/pushNotification/set

Register a webhook URL so the remote agent can push completion events instead of requiring polling.

Message Structure Example

tasks/send (Client → Agent)

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tasks/send",
  "params": {
    "id": "task-abc123",
    "sessionId": "sess-xyz",
    "message": {
      "role": "user",
      "parts": [{
        "type": "text",
        "text": "Research quantum computing trends and summarize in 3 bullets"
      }]
    }
  }
}

Task Response (Agent → Client)

{
  "result": {
    "id": "task-abc123",
    "status": {
      "state": "completed",
      "timestamp": "2025-01-15T10:23:41Z"
    },
    "artifacts": [{
      "name": "summary",
      "parts": [{
        "type": "text",
        "text": "1. Quantum advantage demonstrated..."
      }]
    }]
  }
}
