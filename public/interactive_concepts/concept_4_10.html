The 4 Context Engineering Strategies
① Selective Inclusion
② Progressive Disclosure
③ Compression & Summarisation

🎯
Selective Inclusion
Only include what the current task actually needs — nothing else
The Problem
Naively including all available context (all tools, full history, all docs) wastes tokens and degrades model attention. "Lost in the middle" effect — models focus on start/end.
The Solution
Filter at runtime — include only tools relevant to current task, only the last N relevant messages, only the most similar retrieved chunks. Relevance > completeness.
When to Use
Large tool registries (10+ tools). Agents with rich conversation history. RAG with many candidate chunks.
Techniques
Tool relevance scoring, embedding-based history retrieval, chunk re-ranking (MMR/BM25), semantic routing.
# Only include top-3 relevant tools for current query relevant_tools = rank_tools(query, all_tools, top_k=3) context = build_context( system=system_prompt, history=get_relevant_history(query, k=5), tools=relevant_tools, # selective docs=rerank_chunks(query, chunks, k=3) # selective )
📊
Progressive Disclosure
Start minimal — add context only as the task evolves and more is needed
The Problem
Loading all context upfront means paying token costs even for simple tasks that resolve early. Over-provisioning is wasteful and slow.
The Solution
Inject context in layers: start with query + system prompt, add tool results only when a tool is called, add retrieved docs only if needed. Lazy loading for context.
Example Flow
Turn 1: query only → Turn 2: + tool result → Turn 3: + retrieved doc → Turn 4: answer. Each turn adds only what's needed.
Trade-off
✅ Optimal token use for short tasks | ⚠️ More complex orchestration logic required
# Progressive disclosure pattern context = [system_prompt, user_query] # Layer 1: minimal if agent_needs_tool(response): result = execute_tool(tool_call) context.append(tool_result) # Layer 2: add tool output if agent_needs_retrieval(response): docs = rag_retrieve(query) context.append(retrieved_docs) # Layer 3: add RAG docs only if needed
🗜
Compression & Summarisation
Reduce old context to summaries — preserve meaning, free up tokens
The Problem
Long-running agents accumulate history. After 20+ turns, raw conversation history can consume 40–60% of the context window with diminishing returns.
The Solution
Periodically summarise older turns into a compact "rolling summary". Keep recent turns verbatim; older turns are compressed. Hierarchical summaries for very long sessions.
Compression Techniques
Rolling summary, extractive key-fact extraction, tool-result compression (schema only, not full output), decision log (actions taken, not full trace).
Compression Ratio
Typical: 10:1 to 20:1 — a 2000-token conversation summarised to 100–200 tokens with 85–90% key-fact retention.
# Rolling summary pattern if len(history) > MAX_TURNS: old_turns = history[:-KEEP_RECENT] summary = llm.summarise(old_turns, prompt="Extract key facts, decisions, and unresolved items") history = [summary_message(summary)] + history[-KEEP_RECENT:]
⚡
Dynamic Context Assembly
Build the context window at runtime based on task type, user intent, and available budget
The Concept
A Context Assembler component that runs before every LLM call. It classifies the task, retrieves relevant components (tools, docs, history), and allocates the token budget across them.
Budget Allocation Logic
Code task → more tool defs, less history. Research task → more RAG docs. Conversational → more history, fewer tools. Each task profile has a different allocation template.
Components
Task classifier → Component selector → Token budget allocator → Priority sorter → Context builder → Final assembly.
Production Benefit
Automated, task-aware context management. Reduces need for hand-crafted prompts. Enables consistent performance across diverse task types.
# Dynamic context assembly task_type = classify_intent(user_query) # "research" | "code" | "chat" budget = ContextBudget(total=128000) profile = PROFILES[task_type] # predefined allocation templates context = ContextAssembler(budget, profile).build( system=system_prompt, tools=filter_tools(query, all_tools), history=get_history(budget.history_alloc), docs=retrieve_docs(query, budget.doc_alloc) )
Strategy Selection Guide
You have 20+ tools registered
Most tools are irrelevant for most queries. Including all wastes ~15% of context and degrades attention.
→ Use Selective Inclusion
Agent runs 10+ turn conversations
History grows linearly. After turn 15, raw history dominates the window.
→ Use Compression
Most queries resolve in 1–2 turns
No need to front-load all context. Start minimal and expand only if needed.
→ Use Progressive Disclosure
Agent serves diverse task types
Research vs. code vs. chat need very different context profiles. One template won't fit all.
→ Use Dynamic Assembly
