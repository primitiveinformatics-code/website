5 Cost Optimisation Techniques — Click to Explore
✂️
Prompt Compression
Save 30–60%
Trim system prompts, remove redundant instructions, use shorter few-shot examples

Before: Verbose system prompt with repeated instructions = 800 tokens

After: Compressed prompt with only essential constraints = 320 tokens

❌ "You are a helpful assistant that always tries to be as helpful as possible and provides comprehensive, detailed answers to all questions..." ✅ "Answer concisely. JSON output only. No preamble."
🔀
Model Routing
Save 70–90%
Route 80% of simple sub-tasks to cheap fast models, reserve frontier for orchestration

Most agent tasks are simple: extract, classify, format. Only the planner + synthesis step needs a frontier model.

if task_complexity == "simple": model = "claude-haiku" # $0.25/1M else: model = "claude-opus" # $15/1M # 80% cheap → 90% cost saved
📦
Context Pruning
Save 40–60%
Summarise old turns, keep only relevant tool results, discard intermediate steps after synthesis

In a 5-turn ReAct loop, early turns accumulate in context. After each hop, summarize resolved sub-goals to a 1-line memo.

def prune_context(messages, max_turns=3): if len(messages) > max_turns * 2: summary = llm.summarize(messages[:-4]) return [{"role":"system","content":summary}] + messages[-4:] return messages
💾
Response Caching
Save 20–50%
Cache deterministic LLM responses by input hash — especially for repeated sub-queries in multi-agent systems

Many agent sub-tasks are repeated across sessions (same document, same question). Cache at semantic hash level.

cache_key = hash(model + system_prompt + user_msg) if cache_key in redis: return redis.get(cache_key) result = llm.call(...) redis.set(cache_key, result, ttl=3600) return result
🛑
Loop Guard Rails
Prevent runaway cost
Set hard limits on max turns, token budgets per session, and timeout kill switches

An infinite loop burns $100s per agent run. Always set MAX_TURNS and token budget cutoffs.

MAX_TURNS = 10 TOKEN_BUDGET = 50_000 if turn_count >= MAX_TURNS: return graceful_exit("Max turns reached") if total_tokens > TOKEN_BUDGET: return graceful_exit("Budget exceeded")

Token Anti-Patterns — What to Avoid
🔁
Unbounded Context Accumulation
3–10x token waste
›
Pattern
Appending every tool response to the conversation history without pruning. Turn 5 carries the full content of turns 1–4.
Fix
Summarize resolved sub-goals. Keep a "working memory" of only active context. Use episodic memory store for long tasks.
📄
Full Document Injection
50–500x token waste
›
Pattern
Injecting entire 50-page PDFs into context when only 2 paragraphs are needed. Common in naive RAG implementations.
Fix
Use chunking + retrieval. Only inject the top-3 relevant chunks. Use Self-Query to filter before retrieval.
🧾
Verbose Tool Schemas
200–500 tokens/call
›
Pattern
Auto-generated tool schemas with full docstrings, every parameter described in 3 sentences. Repeated in every request.
Fix
Write concise schemas: name, 1-line description, typed parameters only. 50-token schemas instead of 500-token schemas.
🔁
Redundant LLM Calls
2–5x call count
›
Pattern
Calling LLM to validate output format when a regex check would work. Calling LLM for routing decisions that are rule-based.
Fix
Use deterministic code for structural validation, format checking, and simple routing. Reserve LLM calls for semantic decisions.
🌊
Frontier Model for Everything
10–100x cost overhead
›
Pattern
Using GPT-4o for all tasks including simple extraction, classification, and formatting — because "it's easier to set up."
Fix
Implement Two-Tier architecture. Route 80% of volume to fast/cheap models. Use frontier only for orchestration and synthesis.
