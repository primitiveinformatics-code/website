MCP in Production

Auth, versioning, error handling, rate limits, and observability — everything you need before shipping an MCP-powered agent to real users.

Production Concerns Deep Dive

🔐 Authentication & Authorization Critical
▼

MCP servers must verify WHO is calling them and WHAT they're allowed to do. Two separate concerns.

Authentication (Who Are You?)
  • OAuth 2.0 Bearer tokens in Authorization header
  • API keys passed as custom headers or query params
  • mTLS for server-to-server (hub → downstream server)
  • JWT validation with expiry checks
Authorization (What Can You Do?)
  • Scope-based: token must include required scopes
  • Tool-level ACLs: agent X can call db.query but not db.write
  • Resource-level: only access files in /workspace/
  • Agent identity propagated in X-Agent-ID header
Pitfalls
  • Hardcoded API keys in server config (use secrets manager)
  • No token expiry validation → stale creds stay valid
  • Trusting agent-provided identity without server verification
Production Pattern
Authorization: Bearer {oauth_token}
X-Agent-ID: agent-research-001
X-Request-ID: req-{uuid}
X-Scope: tools.read, fs.read
📦 Versioning & Compatibility Important
▼

Protocol and tool schema versions can drift. Handle this gracefully.

Protocol Version Negotiation
  • Client sends protocolVersion in initialize
  • Server responds with its supported version
  • If incompatible, server returns error code -32600
  • Always support N-1 protocol version for rollout safety
Tool Schema Versioning
  • Add new optional params — always backward compatible
  • Rename/remove params → breaking change → bump version
  • Use tool name versioning: search_v2 alongside search
  • Deprecate old tools with deprecated: true in schema
Breaking vs Non-Breaking

Safe: Add optional param, add new tool, widen return type

Breaking: Remove param, rename tool, change required fields, narrow return type

Canary Deployment Strategy
  • Deploy new server version to 5% of traffic
  • Monitor error rates via observability (see below)
  • Roll back if errors > baseline
  • Promote to 100% after 30-min soak time
🚨 Error Handling & Retries Critical
▼

MCP errors come in two flavors: protocol errors and tool execution errors. Handle them differently.

Protocol Errors (JSON-RPC)
{ "error": {
  "code": -32601,
  "message": "Method not found"
}}
Codes: -32700 Parse Error
       -32600 Invalid Request
       -32601 Method Not Found
       -32602 Invalid Params
       -32603 Internal Error
Tool Execution Errors
{ "result": {
  "isError": true,
  "content": [{
    "type": "text",
    "text": "File not found: /tmp/x"
  }]
}}
Note: isError:true still returns
HTTP 200 — it's app-level error
Retry Strategy
  • Retry on: network timeout, 503, -32603 (transient)
  • Do NOT retry: -32601, -32602 (logic errors)
  • Exponential backoff: 1s → 2s → 4s → 8s → give up
  • Max 3 retries. Log each attempt with request ID.
Graceful Degradation
  • Tool timeout → return error to LLM context, let it decide
  • Server down → agent falls back to cached data or skip step
  • Never silently swallow errors — always put them in context
  • Circuit breaker: stop calling after 5 consecutive failures
⚡ Rate Limiting & Cost Control Important
▼

Agents can exhaust APIs and budgets quickly. Rate limiting is a first-class production concern.

Rate Limiting Strategies
  • Per-agent limits: agent-A max 100 req/min to web.*
  • Per-tool limits: code.run_python max 20 exec/min
  • Global limits: all agents share 1000 req/min total
  • Token bucket algorithm — allows short bursts
When Rate Limit Hit
HTTP 429 Too Many Requests
Retry-After: 12
{ "error": {
  "code": -32000,
  "message": "Rate limit exceeded",
  "data": { "retryAfter": 12 }
}}
Cost Control
  • Track cost-per-tool-call (API costs vary widely)
  • Set hard budget limits per agent per hour
  • Alert when 80% of budget consumed
  • Expensive tools (e.g., GPT-4 Vision) → require explicit unlock
Runaway Cost Pattern
  • Agent loops calling expensive tool repeatedly
  • No loop detection → tool budget exhausted in minutes
  • Fix: max_tool_calls_per_run limit + cost alerting
  • Circuit breaker on cost threshold breach
📊 Observability & Monitoring Required
▼

You can't debug what you can't see. Every MCP call should be traced end-to-end.

What to Instrument
  • Tool call latency (p50, p95, p99)
  • Tool call success/error rates per tool
  • Agent run duration and step count
  • Token usage per run (LLM + tool context)
  • Rate limit hit frequency
Structured Log Fields
{
  "trace_id": "trace-abc123",
  "agent_id": "research-001",
  "tool": "web.search",
  "latency_ms": 234,
  "status": "success",
  "tokens_used": 180,
  "request_id": "req-xyz"
}
Distributed Tracing
  • Propagate trace_id from agent → hub → server
  • Each hop adds a span with timing + metadata
  • Use OpenTelemetry for vendor-neutral tracing
  • Visualize in Jaeger or Grafana Tempo
Alerting Rules
  • Error rate > 5% on any tool → page on-call
  • p99 latency > 10s → investigate server
  • Agent run > 50 steps → possible loop → alert
  • Cost > $50/hour per agent → hard stop

Real-World Failure Scenarios & Fixes

Stale Auth Token

⚠️ Auth Failure

Agent starts a long multi-step task. 45 minutes in, the OAuth token expires. Tool calls start returning 401. Agent has no recovery path — the run fails silently after retries exhaust.

Fix
Implement token refresh before expiry. Check exp claim before each tool call. Use short-lived tokens (15m) + refresh tokens so the MCP client can renew without user interaction.

Cascading Tool Failures

⚠️ Error Propagation

The database MCP server goes down. The agent retries 3x, exhausting its retry budget, then tries alternative tools. Without a circuit breaker, subsequent tool calls still route to the down server, stalling all agents.

Fix
Implement circuit breaker per server. After 5 failures in 60s, mark server as "open circuit" — immediately fail calls for 30s before trying again. Let agents degrade gracefully to cached data.

Runaway Cost Incident

⚠️ Budget Breach

An agent enters a loop calling a paid web search API 400 times in 3 minutes. No rate limit or cost cap was set for this agent type. $800 in API costs in one hour before a human noticed.

Fix
Set hard per-agent hourly cost budgets. Wire up cost tracking into the hub (each tool call has an estimated cost). When budget is 80% consumed, log warning. At 100%, hard-stop the agent run.

Silent Schema Breakage

⚠️ Versioning Failure

A developer renames a required parameter in the db.query tool from sql to query_string. Existing agents still send sql. Server rejects with -32602 Invalid Params. Agents fail silently — no alert fires.

Fix
Never rename required fields without a version bump. Run a contract test suite before any server deploy. Alert on any increase in -32602 errors. Support both old and new param names during a deprecation window.
