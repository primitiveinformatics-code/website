Why Orchestration?

When a single agent isn't enough — the limits that force you to build multi-agent systems, and the four patterns that solve them.

The 5 Limits of a Single Agent
🧠

Context Window Overflow

A complex multi-step task accumulates thousands of tokens — tool outputs, intermediate results, prior reasoning. Eventually it exceeds the context limit and the agent loses earlier context.

→ Orchestration keeps each sub-agent's context small and focused.
⚡

Serial Bottleneck

A single agent does everything sequentially: research → write → review → format. Each step waits for the previous one — no parallelism, even when tasks are independent.

→ Orchestration fans out independent tasks to run simultaneously.
🔧

Specialization Gap

One generalist agent prompted to do everything — research, code, summarize, validate — performs worse than specialized agents with purpose-built system prompts and tool sets.

→ Orchestration routes tasks to expert sub-agents with specialized prompts.
🔁

Error Propagation

If one step fails in a monolithic agent, the entire pipeline fails. There's no isolation, no retry-at-step, no partial recovery. One bad tool call can corrupt all subsequent reasoning.

→ Orchestration isolates failures: one worker fails, others continue.
📊

Observability Black Box

A single long-running agent is opaque — you can see the final output but not what happened at step 7 of 20. Debugging requires replaying the entire run.

→ Orchestration gives you discrete, traceable units with their own logs.
What Is Agent Orchestration?
"Agent orchestration is the design of how multiple AI agents coordinate — who decides what task goes to which agent, how results flow between agents, how failures are handled, and how the overall goal is achieved from a set of specialized parts."

The 4 Orchestration Patterns
Preview: Each pattern is covered in depth in concepts 4.2–4.5. This is your map of the territory.
Pattern 1 · Concept 4.2

Hierarchical (Supervisor-Worker)

A supervisor agent breaks a complex goal into subtasks and dispatches each to a specialist worker agent. Workers report back; supervisor synthesizes the final output. Clear chain of command.

Research pipelines, report generation, multi-step planning
Pattern 2 · Concept 4.3

Network / Swarm (Peer-to-Peer)

Agents communicate directly with each other — no central coordinator. Each agent decides who to hand work to next based on local rules. Emergent coordination from simple agent-to-agent interactions.

Distributed problem-solving, market simulations, debate loops
Pattern 3 · Concept 4.4

Map-Reduce (Fan-Out / Fan-In)

A coordinator fans out identical or similar tasks to N workers in parallel (Map). When all complete, a reducer agent aggregates their outputs into a final result (Reduce).

Batch document processing, parallel web research, code review at scale
Pattern 4 · Concept 4.5

Choreography (Rule-Based Flow)

No central coordinator. Each agent knows its trigger conditions and output targets. Agents react to events or messages — the workflow emerges from the rules embedded in each agent.

Event-driven pipelines, data enrichment chains, ETL workflows
When to Orchestrate vs When to Use a Single Agent

✓ Use Multi-Agent Orchestration when...

  • The task has genuinely independent subtasks that can run in parallel
  • Different steps require radically different skills or tools
  • The total work exceeds one context window comfortably
  • You need specialization: one agent per domain
  • Partial failures should not abort the whole pipeline
  • You need auditable, step-by-step traceability
  • Scale: 100 documents need the same treatment

✗ Avoid orchestration (use single agent) when...

  • The task is simple and fits in one context window
  • Each step depends heavily on all prior steps — parallelism is impossible
  • Orchestration overhead (coordination, latency, cost) exceeds the benefit
  • You're prototyping — start simple, add orchestration when needed
  • A single, clear, linear reasoning chain is all that's required
  • Debugging complexity would outweigh the performance gain
The Complexity Spectrum
Agent system complexity →
Simple / LeanBalancedComplex / Heavy

Single LLM Call

One prompt → one response. No tools, no memory. Appropriate for summarization, classification, simple Q&A.

ReAct Single Agent

One agent with tools: Reason → Act → Observe loop. Handles multi-step tasks within one context window.

Supervisor + 2–3 Workers

First orchestration level. Supervisor delegates, workers execute, supervisor synthesizes. Good starting point.

Map-Reduce Pipeline

Coordinator + N parallel workers + reducer. Powerful for batch tasks. Complexity scales with N.

Full Agent Network

Many specialized agents, dynamic routing, shared memory, event-driven coordination. High power, high ops burden.
