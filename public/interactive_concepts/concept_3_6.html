A2A Artifact Types

📄

Text Artifact

type: "text"

Plain text or markdown. Most common output — summaries, reports, analysis, generated content.

🔢

Data Artifact

type: "data"

Structured JSON data. Use when the caller agent needs machine-parseable output for further processing.

📁

File Artifact

type: "file"

Binary or text file — CSV, PDF, image, code. Includes filename, mimeType, and base64-encoded bytes or a URL.

🖼️

Image Artifact

type: "image" / "inline_data"

Generated images, charts, diagrams. Base64-encoded inline or referenced by URL with mimeType.

Polling vs. Push Notifications

⚠️ Polling (tasks/get)

  • Caller repeatedly calls tasks/get
  • Every N seconds: "Are you done yet?"
  • Wastes network + compute on idle checks
  • High latency to detect completion
  • Simple to implement, no infrastructure needed
Use only for short tasks (< 10s) or when push isn't supported

✓ Push Notifications (Webhook)

  • Caller registers a webhook: tasks/pushNotification/set
  • Agent POSTs to webhook when state changes
  • Zero wasted requests — caller sleeps until notified
  • Low latency for completion detection
  • Requires the caller to host an HTTP endpoint
Preferred for long-running tasks (30s+) in production
