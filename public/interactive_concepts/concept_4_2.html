Hierarchical Pattern: Supervisor-Worker

The most widely used multi-agent architecture. A supervisor orchestrates specialized workers to tackle complex goals that exceed any single agent's reach.

Architecture Overview
The idea: One supervisor agent receives the high-level goal, decomposes it into subtasks, and dispatches each to a specialist worker agent. Workers execute narrowly and report back. The supervisor synthesizes all worker outputs into a final result. Click any node to learn its role.

Task Delegation Flow
1
Supervisor

Receive goal — User sends high-level task: "Produce a competitive analysis of our top 3 rivals."

2
Supervisor

Decompose — Break goal into subtasks: [research each competitor] [analyze positioning] [write comparison table] [review for accuracy]

3
Workers (parallel or sequential)

Execute subtasks — Research Agent scrapes competitor sites. Simultaneously, a context-building agent fetches our own product docs.

4
Workers return results

Report back to supervisor — Each worker returns structured output: {"task_id": "research_rivalA", "result": {...}, "status": "completed"}

5
Supervisor

Check & route — Did all workers succeed? If a worker failed, should we retry or reassign? Are all inputs ready for the next step?

6
Write Agent + Review Agent

Second wave — Write Agent composes the analysis. Review Agent validates facts and flags issues. Both receive the research results as context.

7
Supervisor

Synthesize & return — Assemble all worker outputs into the final competitive analysis document. Return to the user.

Real-World Examples

📰 Research Report Generator

Supervisor: Report Orchestrator
Workers: → Web Search Agent (find sources) → RAG Agent (search internal docs) → Analysis Agent (extract insights) → Writing Agent (draft report) → Citation Agent (add references)

🛠️ Software Development Agent

Supervisor: Dev Orchestrator
Workers: → Planner Agent (architecture) → Coder Agent (write code) → Tester Agent (run tests) → Reviewer Agent (code review) → Doc Agent (write documentation)

🎯 Sales Intelligence System

Supervisor: Sales Analyst
Workers: → LinkedIn Scraper Agent → News Monitor Agent → CRM Data Agent → Email Draft Agent → Scoring Agent (lead priority)
Strengths & Limitations

Strengths

  • Clear separation of concerns — each agent has one job
  • Specialization: purpose-built prompts and tools per worker
  • Partial parallelism — independent workers can run simultaneously
  • Failure isolation: one worker failure doesn't abort others
  • Easy to scale: add more workers without changing the supervisor
  • Debuggable: each worker's I/O is traceable independently
  • The supervisor acts as a natural quality gate before final output

Limitations

  • Supervisor is a single point of failure — if it hallucinates a bad plan, all workers suffer
  • Supervisor must have enough context to evaluate worker outputs — large context requirement
  • Sequential waves add latency (research → write → review can't all run at once)
  • Worker outputs must be structured for the supervisor to parse them reliably
  • Difficult to handle deeply recursive goals without nested supervisors
  • Coordination overhead: each worker call = one additional LLM round-trip
Implementation Pattern
from anthropic import Anthropic
import json

client = Anthropic()

# Each worker is a specialized agent function
def research_agent(topic: str) -> dict:
    result = client.messages.create(
        model="claude-3-haiku-20240307",  # fast, cheap worker
        system="You are a research specialist. Return JSON with 'findings' and 'sources'.",
        messages=[{"role": "user", "content": f"Research: {topic}"}],
        max_tokens=1024
    )
    return json.loads(result.content[0].text)

def writing_agent(research: dict) -> str:
    result = client.messages.create(
        model="claude-3-haiku-20240307",
        system="You are a professional writer. Write clear, concise analysis.",
        messages=[{"role": "user", "content": f"Write analysis from: {research}"}],
        max_tokens=2048
    )
    return result.content[0].text

# Supervisor uses a powerful model with tools to delegate
def supervisor_agent(goal: str) -> str:
    # 1. Plan
    plan_resp = client.messages.create(
        model="claude-opus-4-6",  # powerful supervisor
        system="You are a research director. Delegate to: research_agent, writing_agent. Return JSON task list.",
        messages=[{"role": "user", "content": goal}],
        max_tokens=512
    )
    tasks = json.loads(plan_resp.content[0].text)

    # 2. Execute workers
    research_result = research_agent(tasks["research_topic"])
    draft = writing_agent(research_result)

    # 3. Synthesize final output
    return draft
