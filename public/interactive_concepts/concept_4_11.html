Diagnosis Challenge
🔍 Spot the Failure Mode
Read each symptom — identify which memory failure mode is occurring
"The agent correctly answers Q1 and Q2, but in Q3 it references a fact from Q1 that the user already corrected in Q2."
✅ Stale Memory! The agent retained the old (corrected) fact. The update in Q2 didn't propagate — a classic staleness failure.
"After 30 turns, the agent forgets the user's name, preferences, and early decisions — despite all being in the original context."
✅ Context Truncation! Early context fell off the sliding window. The LLM literally cannot see those tokens anymore.
"User B receives information about User A's account preferences — the agent served User A's memory to a different session."
✅ Cross-User Contamination! A critical security failure — session isolation was broken. Memory retrieved for wrong user_id.
"After 50 tool calls, the agent's responses become slow and incoherent. Logs show the context window at 127K/128K tokens."
✅ Memory Overload! The context window is nearly full. Tool results, history, and docs are competing for the same fixed token budget.
