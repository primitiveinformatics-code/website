The BDI Model

BDI — Beliefs, Desires, Intentions — is the dominant theoretical framework for understanding how rational agents think. Formalised in 1991, it directly underlies LangGraph, AutoGen, and CrewAI today. Knowing BDI lets you reason about why an agent does what it does.

Explore Each Component — B, D, I

Beliefs

What the agent KNOWS

Beliefs represent the agent's internal model of the world — everything it currently understands about its environment, the task at hand, and the results of its past actions. Crucially, beliefs may be incomplete or wrong. The agent acts on what it believes to be true, not on ground truth.

Human analogy: Your current understanding of a situation. You might believe the meeting is at 3pm — that belief guides your actions even if the time was changed and you haven't seen the calendar update yet.
Maps to agent component
Memory — working memory (context window) + long-term vector store
Updated by
Tool call observations — each Observe step updates the agent's beliefs about the world
Key property
May be incomplete, outdated, or incorrect — agents must act under uncertainty
Example in practice
"Stock price is $189.43, EPS data not yet retrieved" — belief state after loop iteration 1

Desires

What the agent WANTS

Desires are the agent's high-level goals — the end states it wants to achieve. Desires are stable: they don't change from loop iteration to loop iteration. They may even conflict (the agent wants to be thorough AND fast). They represent motivation, not commitment.

Human analogy: Your life goals — you want to finish the project, you want to do it well, you want to be home for dinner. These don't change minute to minute, but you can't pursue all of them simultaneously.
Maps to agent component
System prompt goals + user task definition — set once, stable throughout
Key property
Stable across iterations — the goal doesn't change because one tool call failed
May conflict
e.g. "Be fast" vs "Be thorough" — the agent must balance competing desires
Example in practice
"Produce a comprehensive, accurate competitive analysis of the top 3 EV companies"

Intentions

What the agent is COMMITTED to RIGHT NOW

Intentions are the active sub-goals the agent has committed to achieving in the current moment. Unlike desires (stable, high-level), intentions are current and actionable. At any given moment, the agent is executing one intention — a specific plan to move toward a desire.

Human analogy: Right now you intend to finish reading this paragraph before checking your phone. That's a committed, in-progress action — a specific intention that serves your broader desire to learn the material.
Maps to agent component
Current plan execution — the specific tool call being made RIGHT NOW
Key property
Dynamic — changes each loop iteration based on observations and updated beliefs
Drives
Tool calls — every tool call is the execution of a current intention
Example in practice
"Search for Tesla Q3 2024 revenue figures right now" — a specific, committed next step

The BDI Rationality Loop — Click Each Step
1
Perceive
Update Beliefs from new tool output
The agent reads the result of its last action — a tool response, an API result, or an observation from the environment. This updates its internal belief state: what does it now know that it didn't before? This is identical to the "Observe" step in ReAct.
ReAct mapping: OBSERVE → updates Beliefs
2
Deliberate
Select active Desire — is my goal still valid?
With updated Beliefs, the agent asks: which of my Desires is most relevant right now? If an earlier tool call retrieved data that changes priorities, it adjusts. This deliberation step prevents agents from blindly pursuing a goal that the environment has already invalidated.
ReAct mapping: Part of THINK → checking goal validity
3
Plan
Form Intentions from selected Desire
The agent converts the active Desire into a specific, actionable Intention: "Given what I believe and what I want, what is the single best next step?" This produces a concrete plan — which tool to call, with what parameters.
ReAct mapping: Part of THINK → forms specific next action
4
Execute
Act on current Intention — make the tool call
The Intention is executed: the tool call is made, the code is run, the API is called. The agent is now committed to this action. The result will feed back into the next Perceive step, updating Beliefs again.
ReAct mapping: ACT → executes current Intention
↺
Cycle back
Return to Perceive with new observation
The cycle continues. The new tool result becomes the next Observation, updating Beliefs again. The agent re-deliberates, re-plans, and re-executes until the Desire is satisfied or a termination condition fires. This is the BDI rationality loop — and it IS the ReAct loop, just described through a different theoretical lens.
Key insight: BDI and ReAct describe the same cognitive cycle — BDI is the theory, ReAct is the implementation

Key Takeaway
BDI gives you a vocabulary for debugging agents. When an agent fails, ask: is the problem with its Beliefs (bad data / outdated memory), its Desires (wrong goal / conflicting objectives in system prompt), or its Intentions (poor planning / wrong tool call)? Diagnosing which layer broke down is the first step to fixing it. BDI is not just theory — it's your agent's cognitive architecture.
