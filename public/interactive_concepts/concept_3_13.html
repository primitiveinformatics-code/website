RAG Architecture: Two Pipelines

The Indexing Pipeline (offline, runs once) and the Retrieval Pipeline (online, runs per query) — click through every step and component.

The Two-Pipeline Model
Mental model: RAG is two completely separate systems. The Indexing Pipeline runs offline — it's a batch process that transforms raw documents into searchable vectors. The Retrieval Pipeline runs online — it handles live user queries in real time. Each has different performance characteristics, failure modes, and optimization strategies.

📦 Indexing Pipeline

⏱ Runs: offline / on document change
Load & parse source documents
Split into overlapping chunks
Generate embeddings per chunk
Store vectors + metadata in DB

🔍 Retrieval Pipeline

⚡ Runs: every user query, real-time
Receive & optionally rewrite query
Embed query with same model
Search + rerank retrieved chunks
Augment prompt → LLM generates

Step 1: Receive Query

The user's raw question arrives. At this stage, you decide whether to pass it directly to the embedding model or first rewrite it. Short, conversational queries ("tell me more") need prior context added. Ambiguous queries benefit from decomposition into sub-queries. Multi-hop questions may need a query planning step before retrieval.

Document Loader

Connects to source systems and converts documents into a standard format (usually plain text + metadata). Handles authentication, rate limiting, and format parsing (PDF text extraction, HTML stripping, Markdown parsing).

Key decision: How often to re-ingest? Triggers: webhook on document change (best), scheduled polling (simpler), or manual (not recommended for dynamic corpora).

Chunking Strategies — The Critical Decision
Why chunking matters: Chunk too large → retrieval is imprecise, you get irrelevant context. Chunk too small → you lose the context needed to understand a passage. The right strategy depends on your document type. 
# Fixed-size chunking — simplest, least aware of content
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,          # target tokens per chunk
    chunk_overlap=64,        # overlap to preserve context at boundaries
    separators=["\n\n", "\n", " ", ""]  # try paragraph → sentence → word
)

# Semantic chunking — groups sentences by meaning, variable size
from llama_index.node_parser import SemanticSplitterNodeParser

semantic_splitter = SemanticSplitterNodeParser(
    buffer_size=1,            # sentences to consider each side
    breakpoint_percentile_threshold=95,  # similarity threshold for split
    embed_model=embed_model
)
